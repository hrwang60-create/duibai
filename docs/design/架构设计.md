# 「对白」架构设计

> 来源：实验3《软件架构与界面设计》。章节编号沿用原报告。

### 2.3 软件架构与模块设计

#### 2.3.1 软件与外部环境关系图

```mermaid
flowchart LR
    U(["用户<br/>在校学生"])
    S["「对白」软件<br/>(浏览器 + 本地服务)"]
    L["大语言模型服务<br/>(云端 API)"]
    T["语音合成服务<br/>(云端 API)"]
    D[("本地存储<br/>SQLite + 音频文件")]

    U -->|"上传文章 / 选口吻 / 确认"| S
    S -->|"对话稿与音频"| U
    S -->|"文章文本 + 口吻参数"| L
    L -->|"结构化对话稿 JSON"| S
    S -->|"台词文本 + 情绪指令"| T
    T -->|"音频流"| S
    S <-->|"读写文稿与音频"| D
```

**图1 软件与外部环境关系图**：用户为在校学生；「对白」软件本身包含浏览器界面与本地服务两部分；大语言模型服务与语音合成服务均为**外部依赖**，以云端 API 方式调用（实施时若切换为本地模型，则改由本机推理服务承担，图中位置相应移入本地）。本地存储保存文章、对话稿与音频文件，属于本软件自身的数据边界，不对外共享。

#### 2.3.2 软件总体架构图

```mermaid
flowchart TB
    subgraph P["表现层（浏览器）"]
        P1["上传与口吻选择页"]
        P2["生成与确认页"]
        P3["结果页 / 播放器"]
    end
    subgraph A["应用服务层"]
        A1["文章解析服务"]
        A2["对话生成编排"]
        A3["确认与修订服务"]
        A4["音频合成调度"]
    end
    subgraph Dm["领域层"]
        C1["实体：文章 / 段落 / 对话稿 / 对话条目 / 口吻"]
        C2["规则：听觉可用性校验 / 出处校验 / 可疑处规则"]
    end
    subgraph AI["AI 能力层"]
        I1["LLM 客户端（结构化输出）"]
        I2["Prompt 模板与口吻配置"]
        I3["TTS 客户端（分句与情绪指令）"]
    end
    subgraph F["基础设施层"]
        F1["SQLite 数据库"]
        F2["音频文件存储"]
        F3["日志与错误记录"]
    end

    P --> A
    A --> Dm
    A --> AI
    A --> F
    AI --> F
    Dm --> F
```

**图2 软件总体架构图**：采用分层架构。**表现层**负责页面与交互；**应用服务层**负责流程编排（解析、生成、确认、合成）；**领域层**保存核心实体与校验规则；**AI 能力层**封装所有对外部模型的调用，是唯一与模型服务直接交互的层；**基础设施层**提供存储与日志。依赖方向自上而下，AI 能力层与基础设施层不反向依赖表现层，从而保证模型服务可被替换（对应表8 的替代方案）。

#### 2.3.3 模块职责与依赖关系

```mermaid
flowchart LR
    IN["用户输入<br/>文件 + 口吻"] --> P["表现层"]
    P --> PAR["文章解析服务"]
    PAR --> DB1[("段落数据")]
    DB1 --> PRO["Prompt 组装"]
    PRO --> LLM["大语言模型生成"]
    LLM --> CHK["结构 / 出处 / 括号残留校验"]
    CHK --> DB2[("对话稿数据")]
    DB2 --> CONF["用户确认可疑处"]
    CONF --> TTS["语音合成（双音色）"]
    TTS --> AUD[("音频片段")]
    AUD --> PLAY["播放与逐句回看"]
    PLAY -->|"修改某句"| TTS
```

**图3 模块依赖与数据流向图**：展示核心流程中数据在各模块之间的流动顺序。数据从用户输入开始，经解析落库为段落数据；再由 Prompt 组装提交模型生成，生成结果必须通过结构、出处与括号残留三项校验后才能落库为对话稿；对话稿须经用户确认才进入语音合成，合成结果落为音频片段供播放。图中最后一条回边对应"单句修正后仅重做该句"。
