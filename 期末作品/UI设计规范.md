# 「对白」UI/UX 设计规范

> 制定依据：用户给出的「顶级产品设计师」提示词要求 —— 先重想产品、再定视觉语言、拒绝 AI 模板套路。
> 生成方式：**手写 HTML/CSS 设计稿 → 无头浏览器精确渲染**（不用 AI 画图，避免"AI 模板感"）。
> 制定时间：2026-10-02

---

## 零、先重想产品，再画页面

| 问题 | 回答 |
| --- | --- |
| 用户是谁 | 在校学生，在通勤 / 睡前 / 做家务这些**手眼被占用**的时刻 |
| 为什么需要 | 不是"没人念"，而是**念出来听不进去**：书面语不适合听、单声道没对话感、光听没法核对 |
| 最核心的任务 | 把一篇文章变成**能听懂、听不累、可核对**的音频 |
| 打开后最想立刻完成 | 丢一篇文章进去，然后开始听 |
| **什么该成为视觉核心** | **两个人的对谈本身** —— 不是播放器 |
| 最大创新点 | 不是朗读，是**两个人在聊**，且每句能点回原文 |
| 最容易被记住的特征 | **"我在旁听一场正在发生的对话"** |

**结论：这个产品的视觉核心是「对话」，不是「音频」。**

---

## 一、范式转变（本次设计最关键的一步）

传统听觉产品的默认范式是**播放器**：进度条 + 播放键 + 一列静态文字稿。
这个范式对「对白」是错的 —— 它把产品的最大创新（双人对谈）压缩成了一条进度条。

| | 传统音频产品 | **「对白」** |
| --- | --- | --- |
| 主界面 | 播放器 | **对话流** |
| 用户心理 | 我在**操作**一个播放器 | 我在**旁听**一场对谈 |
| 进度表达 | 时间轴百分比 | **对话进行到哪一句**（位置即进度） |
| 文字稿的地位 | 附属品（在播放器下面） | **文字稿就是主界面**，音频是它的声音 |
| 可疑处确认 | 弹窗打断流程 | **对话在这里"卡住"**，像真实谈话里的追问 |

---

## 二、★ Signature Interaction（记忆点交互）

**「对话流 + 插话」** —— 别人第一次看到就能记住的那一个交互。

### 对话流的形态
- 台词以**纵向流**呈现，**当前句在画面中央，最大最亮**
- 已播与未播的句子**带景深**：更小、更淡、更靠边（像镜头景深，不是列表）
- 说话人**不用头像、不用气泡**，只用**字的颜色**区分 —— 这是最克制也最独特的选择
- 左侧一条**细竖轨**表示进度（一个点沿着轨移动），**代替进度条**

### 核心动作
| 动作 | 行为 | 像什么 |
| --- | --- | --- |
| 点任意一句 | 该句浮到中央并重播 | 往回听一耳朵 |
| 侧滑某句 | 「改这句」 | 编辑一条消息 |
| **遇到可疑处** | **对话流在此停住**，两人之间浮出朱红的 `?`，**必须回应才继续** | **你在对话里被追问了一句** |

**为什么这个交互值得记**：它把"确认 AI 结果"这个枯燥的审核动作，
变成了对话剧情的一部分 —— 用户不是在校对机器输出，而是在**参与一场谈话**。

## 三、反模板审查（先自我否定）

**明确禁止**（这些正是"AI 模板感"的来源）：

| 禁止 | 本设计的选择 |
| --- | --- |
| 深色背景 + 蓝紫渐变 + 发光边框 | **浅色纸感底 + 墨 + 朱**，零渐变、零发光 |
| 玻璃拟态 | 不用 |
| 滥用圆角卡片 | **取消卡片化** —— 用**分隔线 + 留白 + 字号层次**分区 |
| 大面积渐变背景 | 纯平色 |
| 到处写"AI" | 全篇不出现"AI"字样，用"改写""对谈"这类产品语言 |
| 无意义粒子 / 霓虹 | 不用 |
| 巨大标题 + 一堆卡片 | 标题克制，主体是**内容本身** |
| 功能平均排列 | 建立**一级/二级/三级**视觉焦点 |
| 科技感靠特效 | **科技感来自排版精度、动效节奏、信息组织** |

**自我审查结论**：现有实现（首页三张圆角卡片堆叠 + 青绿/橙配色）**正是要推翻的那类设计**。
本次规范是一次**设计重做**，不是微调。

## 四、Design System

### 4.1 色彩 —— 「墨与朱」两色系统

只有**两个彩色**，其余全是中性灰。这是克制，也是辨识度。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ink` | `#1A1A18` | 主文字 · **说话人甲** · 品牌 |
| `--ink-2` | `#5A5750` | 次级文字 |
| `--ink-3` | `#8C877E` | 提示 / 禁用 |
| `--paper` | `#F5F2EA` | 页面底（纸感，非纯白） |
| `--paper-2` | `#EDE9DF` | 分区底 / 输入底 |
| `--line` | `#E2DDD2` | 分隔线（**主分区手段**） |
| `--vermilion` | `#C8452C` | **说话人乙** · 强调 · 可疑标记 · 关键操作 |
| `--vermilion-soft` | `#F6E4DE` | 朱的浅底 |
| `--amber` | `#8A6A1F` | 仅用于「注意」类提示，**唯一第三色** |

> **为什么是墨与朱**：中文手稿的"朱批"传统 —— 正文是墨，批注是朱。
> 「对白」本质就是**一份被两个人批注过的文本**。这个意象既贴产品，又完全避开 AI 模板配色。
> ⚠️ **现有实现的青绿 `#0F6E56` / 橙 `#FF7A59` 将被替换为本套色板。**

### 4.2 字体系统（小程序内用系统字体）

| 层级 | 字号(rpx) | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- |
| Display | 56 | 500 | 1.25 | 首页主张（"把文章，聊给你听"） |
| H1 | 40 | 500 | 1.3 | 页面主标题 |
| H2 | 32 | 500 | 1.35 | 分区标题 |
| **台词** | **36** | 400 | **1.7** | **对话流台词（比正文大，因为听时离屏幕远）** |
| Body | 28 | 400 | 1.6 | 正文 |
| Caption | 24 | 400 | 1.5 | 辅助说明 |
| Label | 20 | 500 | 1.4 | 标签 · 元信息 |
| Numeric | 等宽 | 500 | — | 序号 / 时长 |

**关键**：台词的**字号与行高**是全系统最大的一档 —— 因为用户常常是"扫一眼屏幕再回到耳朵"，
字必须大。这是**为使用场景服务的设计决策，不是审美偏好**。

### 4.3 间距系统（8 的倍数）

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`（rpx 语境下按 2 倍：8/16/24/32/48/64/96/128）

**规则**：同组元素用 `16`，组与组之间用 `48`，区块之间用 `96`。
**不允许"哪里空了塞一个东西"** —— 间距必须成体系。

### 4.4 圆角与层次

- **圆角只用两档**：`胶囊（用于按钮/标签）` 与 `12rpx（用于输入框/浮层）`
- **❌ 不给内容卡片加圆角** —— 内容靠分隔线与留白分区，不靠卡片
- **阴影几乎不用**：仅浮层（bottom sheet / popup）用一层极弱阴影
- 层次靠 **背景层级 + 分隔线 + 空间** 建立，不靠阴影

### 4.5 图标

- 线性图标，统一 **2rpx 描边**、统一 44rpx 尺寸
- 能不用图标就不用 —— **优先用文字**
- 不用彩色图标

### 4.6 动效规范

| 场景 | 时长 | 曲线 | 说明 |
| --- | --- | --- | --- |
| 台词上移（流推进） | 420ms | ease-out | 透明度 + 位移 + 缩放同时变，形成景深 |
| 按压缩放 | 120ms | ease-out | scale 0.97 |
| 页面进入 | 280ms | ease-out | 淡入 + 上移 8rpx |
| 可疑处浮出 | 360ms | ease-out | 从中心放大 + 淡入 |

**原则：动画服务于信息。** 台词推进的动画**必须让人看懂"刚才说到哪、现在说到哪"**，
而不是为了炫技。**所有动效必须有理由，无法解释的一律删除。**

## 五、信息架构（不套"顶部导航 + 左菜单 + 卡片"）

小程序端：**底部 3 项**（对白 / 历史 / 我的），但**首页不是卡片堆叠**，而是：

```
① 品牌行（极小，「对白」+ 右侧「我的」）
② 首屏主视觉：一段【活的示例对谈】   ← 视觉记忆点，直接演示产品价值
③ 一句主张（Display 字号）
④ 主操作：投入一篇文章
⑤ 最近（一条，非卡片，用分隔线）
```

**三级视觉焦点**：
- 一级：示例对谈（用户先看这个 → 立刻懂）
- 二级：主操作按钮（接着看这个 → 知道该干嘛）
- 三级：品牌行 + 最近（余光扫到即可）

**三秒法则回答**：这是干什么的（看到对谈）· 我该做什么（看到投入按钮）· 为什么值得用（对谈比朗读好懂）。

## 六、三个原创 UX 方向（含选型）

| # | 方向 | 实际价值 | 认知成本 |
| --- | --- | --- | --- |
| **1** | **对话流代替播放器**（✅ **选定为核心设计语言**） | 进度即位置，一听就知道说到哪；台词与音频合一，不用在播放器和文字稿之间来回看 | 降低（不用理解时间轴） |
| 2 | **确认即剧情**：可疑处让对话"卡住" | 把枯燥的审核变成剧情节点，用户更愿意认真确认，**直接提升结果可信度** | 降低（不需要读懂审核表单） |
| 3 | **口吻的同句对照**：选口吻时并排展示**同一句话的 6 种说法** | 一眼看出区别，不用逐个试；减少反复重生成 | 降低（不用想象"抬杠"是什么样） |

**选型结论**：以 **1** 为核心设计语言（它定义整个产品的主界面），2、3 作为配套创新点实现。

## 七、状态与微交互（不留空白态）

每个页面必须齐备：**Loading · Empty · Error · Success · Disabled · Skeleton · First-use**

| 状态 | 设计 |
| --- | --- |
| Loading | 骨架屏（不是转圈）—— 用灰条模拟台词行，因为**台词行是已知结构** |
| Empty（历史） | 「还没有对谈过。投一篇文章，听两个人把它聊开。」+ 主操作 |
| Error | 朱色标记 + **具体原因 + 下一步动作**（不写"出错了"） |
| First-use | 首页本身承担首次引导 —— **示例对谈即教程**，不需要额外的新手引导层 |
| 生成中 | **不编造百分比**。用对话流的"预演"形态 + 已用秒数（诚实） |

## 八、文案规范

- 简短、有信息量、有动作导向、有品牌语气
- **不出现"AI""智能""强大"这类空词**
- ❌「点击这里开始使用我们的强大 AI 功能」
- ✅「把文章，聊给你听」
- ✅「投一篇文章，听两个人把它聊开」
- ✅「这里听不清？改一下就行」（替代「编辑此对话条目」）

**语气定位**：像一个懂行的朋友在说话，不像产品说明。

## 九、与现有实现的落差（下一步要改什么）

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 配色 | 青绿 `#0F6E56` + 橙 `#FF7A59` | **墨 `#1A1A18` + 朱 `#C8452C` + 纸 `#F5F2EA`** |
| 首页 | 三张圆角卡片堆叠 | **活的示例对谈 + 大主张 + 主操作**，去卡片化 |
| 核心页 | 计划做 AudioPlayer + LyricSync（播放器范式） | **对话流**（新组件 `ConversationStream`） |
| 确认页 | 计划做表单式确认 | **对话"卡住"式确认** |
| 圆角/阴影 | 到处圆角卡片 | 只用两档圆角，**阴影几乎为零** |

> 组件命名同步调整：`LyricSync` → **`ConversationStream`**（它不再是"歌词同步"，而是主界面）。
