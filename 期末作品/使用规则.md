## 一、令牌使用规则

### 1.1 选灰之前，先问：这段文字落在「卡片」上还是「页面」上？

**这是最容易踩的一条。** 纸阶有两层，同一个令牌压两个底色的对比度**差约 0.45**：

| 令牌 | 压**卡片底** `#F5F2EA` | 压**页面底** `#EDE7D9` | 结论 |
| --- | --- | --- | --- |
| `$dui-ink2` `#5A5750` | 6.44 | 5.85 | 两处都能用 |
| `$dui-ink3` `#6C6760` | 5.01 | **4.55** | 两处都能用（**页面底那档是下限**） |
| `$dui-ink4` `#756E61` | **4.51** | **4.10** | ⚠️ **只能用于卡片底**；页面底不可用于正文 |
| `$dui-ink5` `#C7C1B7` | 1.60 | 1.45 | 只做装饰，**绝不承载文字** |

> **为什么这条必须反复讲**：`$dui-ink4` 当初只在注释里标了"卡片 4.51"，
> 于是被用到了页面底的对话流上（4.10），再叠 opacity 跌到 **2.57** —— 主屏不可读。
> **只标一半的数值比不给更危险，因为读的人会信任它。**

**用法**：卡片内四级文字（占位、卡片内元数据）用 `ink4`；页面上的文字最低用 `ink3`。

### 1.2 不要用 `opacity` 降文字层级

**判据**：降透明度会**同时削弱对比度**，是可用性问题，不是"次级感"的手段。

| 做法 | 结果 |
| --- | --- |
| `$dui-vm` + `opacity: .7`（想让它"次级"） | 压卡片底 **3.01** ❌ |
| `$dui-vm` 原样 | 压卡片底 **4.97** ✅ |
| 想要次级感 | **用字号**（`$dui-fs-caption`）**或用更浅的色** |

### 1.3 装饰 vs 文字：看它是「画出来的」还是「打出来的」

**判据**：
- **用字符渲染的**（`·` `—` `/` 当分隔用）→ **它是文字**，必须过对比度。`ink5` 不许用
- **用 CSS 画的**（`<view>` 的 1px 线、背景色块、border 三角）→ 才是"装饰"，`ink5` 可用

> **为什么**：`·` 承担"这两个是不同字段"的语义。看不见就会把
> `播客对谈 · 23 句 · 01:48` 读成 `播客对谈 23 句 01:48` —— **字段边界丢失**。
>
> **推论：想让一个元素"更轻"，正确做法是换形态，不是降对比度。** 跟 1.2 同理。

### 1.4 朱色的判据

**朱是「批注色」**，只标记**内容里需要注意的东西**（某句台词、某处待确认、某个可执行动作）。

| 问自己 | 答案 |
| --- | --- |
| 去掉这处朱色，用户会**漏掉内容信息**吗？ | 会 → **该用朱** |
| 去掉后只是"少个装饰"或"当前位置不明"吗？ | 是 → **不该用**（导航 chrome、分区线、纯装饰一律不用） |

⚠️ **朱绝不能铺成一大块** —— 铺开就从"批注"变成"主题色"，克制感全丢。
朱色的图标方块、朱色的整块底，都是踩过的。

**例外（唯一）**：`$dui-vm` 文本本身**可以**是朱色的，只要字号够、且不叠 opacity。

## 二、组件与交互规则

### 2.1 按压类：`.press` 与 `.press-ink` 不能混用

| 元素底色 | 用哪个 | 反馈方式 |
| --- | --- | --- |
| 纸 / 卡片 / 透明 | **`.press`** | 正常：`scale(.94)`；减动效：底色变深一档 |
| **墨**（`background-color: $dui-ink`） | **`.press-ink`** | 两种模式都是 `opacity: .88`，**无位移** |

**为什么墨底不能用 `.press`**：它在减动效下靠"底色变深"表达，而 `$dui-press` 是纸色系 ——
墨底元素一旦挂 `.press`，减动效下会从墨底变浅底、文字仍是 `$dui-on-ink`（近白），**对比度直接塌**。

**为什么墨底不用缩放**：墨底是重色块，在它上面做位移，视觉冲击远大于纸底 —— 那是"晃动"不是"按下"。

**⚠️ 底色会随状态切换的元素**（如"选中"变墨、未选中变纸），要**用单一表达式产出互斥对**：
```
:class="{ on, press: 选中态为假, 'press-ink': 选中态为真 }"
```
不要写两个独立的 `hover-class` 各自判断 —— 那会出现中间态。

### 2.2 触摸目标 ≥ 88rpx（44pt）

- 图标按钮、正文行、chip、列表行：**最小 88 × 88rpx**
- 用 `min-height` 而不是 `height`（内容多时不被截断）
- 纯文字链接（`出处` / `改这句`）也要撑够
- **验收脚本扫的是 `height: 72/76/80rpx`** —— 那是历史遗留值，出现即需核对

### 2.3 图标：不能内联 `<svg>`

**微信小程序渲染器不认 `<svg>` 标签。** uni-app 会把它原样透传到 WXML，
编译通过、产物里也看得到，但**运行期什么都不画，且不报错、不警告**。

**三种可用画法**（按可靠性排序）：

| 画法 | 用在哪 | 注意 |
| --- | --- | --- |
| **CSS 画**（`border` 三角 / 细线） | 播放三角、分隔点 | 不依赖任何字体，最稳 |
| **`<image>` 引 PNG** | tabBar 图标等复杂图形 | 颜色固定，不能跟随文字色 |
| **字符**（`→` `↑` `›` `·`） | 简单箭头 | **必须先确认该字符在同页已能正常显示**。`↑`(U+2191) 与 `→`(U+2192) 同区块，字体覆盖一致 |

⚠️ **`▶`(U+25B6) 在几何图形区，字体是否收录不确定** —— 不要赌，用 CSS 画。
（参见项目里 `每日一集` 的"听整集"三角。）

## 三、页面结构规则

### 3.1 每个内容块前面都有「标签行」

```html
<view class="sec-head">
  <text class="sec-label">今 日 一 集</text>   <!-- 宋体 + 宽字距 -->
  <text class="sec-count">04:02</text>          <!-- 等宽 -->
</view>
```
**高度固定 30rpx**（`App.vue` 里的 `.sec-head`）。它既是块与块之间的呼吸位，
也保证每个块的开头结构一致 —— **不要因为某块内容多就省略它**。

### 3.2 一屏最多 3 块内容

超过 3 块，节奏就散，用户不再知道先看哪。多的内容下沉到二级页（历史、每日一集）。

### 3.3 三态必须区分成因

**空 ≠ 空**。至少区分三种，文案和动作都要不同：

| 态 | 文案方向 | 动作 |
| --- | --- | --- |
| **未登录** | "登录后，这里会存下你聊过的每一场" | 去登录 |
| **真没数据** | "还没聊过" | 去投一篇文章 |
| **读取失败** | "记录没读出来" | **重试** |

⚠️ **读取失败绝不能显示成"没数据"** —— 用户会以为数据丢了。
新增一个 `loadError` 状态，别复用 `list.length === 0` 那个分支。
`loadMore` 失败也要给 toast，不是静默。

### 3.4 防御式写法

props 有 `default` **不等于**运行时不会拿到 `undefined`（父组件显式传 `undefined` 时 default 不生效）。

```js
// ❌ 抛错 → 点按钮整块卡死
this.draft = this.line.text
// ✅ 不抛 → 只是草稿为空
this.draft = (this.line && this.line.text) || ''
```

**判据**：`.text` / `.map` / `.length` 这类"假定对象存在"的访问，
在自己组件里加一层 `&&` 成本几乎为零，收益是消掉一整类运行期崩溃。

## 四、手工同步点（SCSS 变量够不着的地方）

⚠️ **这是全站唯一的"改了令牌不会自动生效"的地方。**

| 面 | 位置 | 涉及 |
| --- | --- | --- |
| **① 原生 tabBar** | `pages.json` | `$dui-ink`→`selectedColor`、`$dui-ink3`→`color`、`$dui-card`→`backgroundColor`、**`$dui-page`→`globalStyle` 的 4 个字段** |
| **② JS / 内联 SVG 属性** | 各 `.vue` 的 `<script>`、模板里的 `stroke=` | `confirmColor`、菜单项 `color`、图标 `stroke` |

**`$dui-page` 最容易漏** —— 它藏在 `globalStyle`（不在 `tabBar`），
一处改要连带 4 个字段。**漏了它，全站每页顶部都有一道色差。**

**改令牌值的正确顺序**：
1. 先**列出**被硬编码引用的令牌（查 `pages.json` + grep `.vue` 的 `<script>`）
2. 改 `uni.scss` 的值
3. **同步** `pages.json` 与 JS 里的字面量
4. 重扫 `.vue` 有没有写死色值
5. 若改的是亮色系（`ink3`/`ink4`/`ink5`）→ **重导 tabBar 图标 PNG**
6. 重新编译并 grep 产物核对

## 五、验收怎么跑

```bash
cd 期末作品

# 全量（含编译）
node 验收.mjs

# 只跑 2–7 项（跳过编译；沙箱内 node 不能 spawn 子进程时用这个）
node 验收.mjs --no-compile
```

| # | 检查 | 判定 |
| --- | --- | --- |
| 1 | 语法/编译 | FAIL |
| 2 | 令牌合法性（引用的 `$dui-*` 都要有定义） | FAIL |
| 3 | 写死色扫描（`<style>` 内不得有旧值字面量） | WARN（JS 层的合法硬编码只登记） |
| 4 | 动效保护（>200ms 的必须在 `prefers-reduced-motion` 内） | FAIL |
| 5 | 触摸目标（扫 `height: 72/76/80rpx`） | WARN（需人工核对是否可点） |
| 6 | 产物核对（新值进入 `app.wxss` / `app.json`） | FAIL |
| 7 | **内联 `<svg>`** | **FAIL**（小程序静默丢弃，没有例外） |

**退出码**：0 = 无 FAIL，1 = 有 FAIL（可接 CI）。

### ⚠️ 跑之前必做两件事

1. **停掉 HBuilderX GUI 的自动编译** —— 它会在你读产物时中途清空/重写
   `unpackage/dist/`，导致**误报"令牌值缺失"**。（脚本已加稳定性守卫，手工核对时仍要注意。）
2. **"全局类有没有被用上"要数 `.wxml`，不是 `.wxss`** ——
   `app.wxss` 只放**定义**，**类的用法在各组件的 `.wxml`**。数错文件会得出"没生效"的错误结论。

### 另两个测试

```bash

node 复现历史跳转.mjs      # 端到端：历史 → 结果页 的传参与载入
```
