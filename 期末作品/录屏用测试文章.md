# 录屏用测试文章

> 三篇，长度递增。**从最长的那篇开始录**（它最容易触发"可疑处"确认项，那是最值钱的一段）。
> 复制方法：全选代码块 → 复制 → 粘到小程序的输入框。

---

## 篇 ① 短篇（约 260 字）· 跑通流程用

**为什么先跑这篇**：生成快（5–8 秒），适合先把整条链路走一遍、热手。

```
光合作用为什么被拆成两个阶段

很多人以为光合作用就是"叶子在阳光下制造糖"，其实它被拆成两个阶段，是因为这两件事需要的条件完全不同。

第一个阶段叫光反应，发生在类囊体膜上。它的核心任务是把光能变成化学能，具体做法是拆开水分子、释放氧气，同时把电子和质子暂存起来。这一步必须有光，没有光就完全停摆。

第二个阶段叫暗反应，发生在叶绿体基质中。它不再需要光，而是拿第一阶段暂存的电子和质子，把二氧化碳固定下来，最终合成糖。

之所以要拆开，是因为两类反应的条件互斥：光反应需要光，暗反应需要二氧化碳和温度。如果强行合并成一步，就没法在夜里继续工作了——植物只能白天产糖，效率极其低下。

拆分之后，植物可以把两个阶段解耦：白天光照强时多产糖，夜里虽然不产糖，但已经合成好的糖可以继续被使用。

有意思的是"暗反应"这个名字其实有点误导。它并不是"在黑暗中进行"，而是"不需要光直接参与"。只是因为它不依赖光，才被归到暗反应。
```

## 篇 ② 中篇（约 900 字）· 正式录屏用

**为什么用它**：长度适中，生成约 15–25 秒，六到十句台词，景深层次刚好。

```
为什么读完一篇长文章，转身就忘了

你有没有过这种体验：晚上读完一篇三千字的文章，觉得很有收获；第二天跟人复述，只记得开头结尾两句，中间全是一片模糊。

这不是记性问题，是阅读方式的问题。

原因之一是线性阅读天然缺乏结构。眼睛从左到右、从上到下扫过每一行，注意力是靠时间维持的，一旦走神，就断了。而且文章没有告诉你"这里最重要"，所有段落看起来同样重要，于是大脑不知道该优先记住什么。

对比一下对话就清楚了。两个人一问一答，问句会制造期待，答句会给出重点，而答句往往比问句长。这种不对称让大脑自动完成了一次压缩：长的、具体的内容被留下，短的、过渡的内容被丢掉。

所以，把文章改写成对话，本质上是替读者做了一次信息筛选。留下来的不是"读过的全部"，而是"值得记住的部分"。

不过要说明一点，对话化不是万能的。技术文档、法律条文这类内容本身就有严格的结构，改成对话反而可能损失精度。这时候更适合的是加小标题、做摘要、给索引，而不是拟人化。

判断标准很简单：这篇文章是"讲道理"还是"查事实"？讲道理可以对话化，查事实就该保持原样。
```

## 篇 ③ 长篇（专业内容，**录屏首选**）· 用来触发"可疑处"

**为什么录屏要用这篇**：内容是**真实教材片段**，专业术语密集。大模型生成对谈时**极有可能用上原文没有的术语**（比如把"多路复用"说成"信道共享"），**这就会触发确认页的"术语超纲"标记** —— 而那正是作业里最值钱的一段。

> **如果这篇没触发可疑项**，换一个内容再试，或者多跑几次（生成是随机的）。**确认页一定要在录屏里出现。**

```
计算机网络：数据链路层概述

数据链路层在协议栈中位于物理层之上、网络层之下。它要解决的核心问题是：把物理层提供的、可能出错的比特流，转换成网络层可以放心使用的、可靠的链路。

它做三件事。第一是封装成帧，也就是给一段数据加上首部和尾部。首部里通常包含目的地址，控制信息放在尾部。这样接收方才能知道一帧从哪里开始、在哪里结束。成帧是链路层最基础的功能，因为物理层只负责传比特，不知道数据的边界在哪里。

第二是差错检测。常见的做法是 CRC，即循环冗余校验。发送方把数据段当成一个多项式，除以一个双方约定的生成多项式，把余数作为帧校验序列附在帧尾。接收方用同样的方法再算一次，两次余数不同就说明传输中出了错。

第三是流量控制。如果发送方比接收方快，接收方的缓冲区会溢出，帧就被丢弃了。流量控制通过让发送方知道接收方的剩余能力来避免这一点。

需要特别注意的是，链路层提供的是逐帧的可靠交付，它不能保证一条消息的所有帧都按序到达。当一条消息跨越多个帧、而中间某帧出错时，链路层只知道这一帧坏了，它无法把整条消息重新组装。要做到端到端的可靠交付，必须由更高层来实现。
```

## 录屏建议顺序

```
① 用篇 ③ 录「生成 → 确认 → 播放」   ← 最重要，要触发可疑项
② 如果篇 ③ 没触发，换一篇再来一次
③ 用篇 ① 快速跑一遍完整链路（备用）
```

**篇 ② 留作备用**：如果篇 ③ 生成失败或者对话质量不好，用它顶上。

---

## 一句提醒

**粘贴长文章时，微信小程序的 textarea 可能有长度限制。** 如果篇 ③ 粘不进去，改用篇 ②。
