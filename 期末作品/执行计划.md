硬指标：6+ 页面 · 10+ 组件 · 云库含 `users`/`banners` · 大模型 API · 管理端（加分）

### 取舍红线：**「能演示」优先于「功能全」**

| 必须做对 | 可以凑合 |
| --- | --- |
| 页面能被逐个验证 | 页面精美度 |
| 组件能被逐个指出 | 组件复用度 |

⛔ **管理端是加分项，不能为它牺牲核心链路。** 核心链路跑不通，加分项一分都拿不到。

### ★ 执行顺序与依赖（**只排先后，不排日期**）

**总链**：`A 打通链路` → `B 铺 C 端页面与组件` → `C 管理端` → `D 打磨与交付物`

**为什么必须是这个顺序 —— 每一步的依赖理由**：

| 序 | 阶段 | 为什么不能提前 / 推后 |
| --- | --- | --- |
| **1** | **A 核心链路** | 它**决定云函数返回的数据结构**。先铺页面再改结构 = 页面全部返工（上一轮已经踩过这个坑） |
| **2** | **B C 端页面与组件** | ① 组件是页面的零件，**必须先有组件再有页面**；② 必须在 A 之后，因为接口那时才定型 |
| **3** | **C 管理端** | ① 依赖 B 里的登录态与表格组件；② 它是**加分项**，必须让位于 P0，排在 C 端之后 |
| **4** | **D 打磨与交付物** | 依赖前面全部产出。**没有产物时做交付物毫无意义** |

**各阶段的串行链（每步做完并检查通过，才进下一步）**：

```
A：A1 mock → A2 selftest → A3 CLI 调用 → A4 本地单测 → ［A5 配 Key（你）］ → A6 真实生成 → A7 TTS → A8 端到端
B：B1 生成中 → B2 确认 → B3 结果 → B4 历史 → B5 我的 → B6 原文 → B7 错误页
C：C1 入口 → C2 概览 → C3 用户 → C4 Banner → C5 口吻 → C6 改 admin
D：D1 统一态 → D2 架构图 → D3 录屏 → D4 导出脱敏 → D5 打包 → D6 编程比例
```

**可以并行的两处**：
1. **A5 等你配 Key 期间，B1 / B2 可以同时开工** —— 它们不依赖真实 Key，只依赖 A1–A4 已定型的接口。
2. **D2 信息架构图**不依赖任何代码，任何时候插进去做都行。

**关键路径（整条链上唯一会被卡住的地方）**：

```
A5 配 Key（在你手上） → A6 真实生成 → A7 TTS → A8 端到端
```

**这四步串成一条，且起点在你手上**；其余所有步骤都在我手上，可连续推进。
**所以：A5 越早办，整条链越早动起来。**

## 每步的固定动作（不得省略）

1. **做之前**：把该步的任务标记为「进行中」
2. **做完后立刻检查**，检查必须拿**可复核的实证**：
   - 代码类 → `node --check` / 提取 `.vue` 的 script 块做语法检查

   - 界面类 → 必须看到渲染结果（截图或产物核对）
