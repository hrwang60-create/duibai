## 1. 触摸目标清单

### 1.1 达标线
- 微信小程序建议 **≥ 88rpx × 88rpx（44pt × 44pt）**。文字链接类若视觉尺寸小，**用透明内边距/`::after` 扩热区到 88rpx 即可，不必放大视觉**。
- 相邻可点目标的**间距 ≥ 16rpx（8pt）**，避免误触。
- 触控与指针的差异：小程序以手指为主，**按压态必须有**（见第 4 节），且**不允许只有 hover 才可见的操作**。

## 2. 对比度（WCAG 2.1 AA）

用真实色值经 WCAG 相对亮度公式计算（`#EDE7D9` 页面底 / `#F5F2EA` 卡片底）。

### 2.0 选色前的第一问：这段文字落在「卡片」还是「页面」？（**必读**）

纸阶有两层（`$dui-page #EDE7D9` / `$dui-card #F5F2EA`），**同一个令牌压两个底色，对比度不同**（卡片更亮，灰字压卡片上对比度更高）。所以**选灰之前先问：这段文字落在卡片上、还是页面上？**

| 令牌 | 压卡片底 | 压页面底 | 两层都可用于正文？ |
|---|---|---|---|
| `$dui-ink2 #5A5750` | 6.44 | 5.85 | ✅ 两层都行 |
| `$dui-ink3 #6C6760` | 5.01 | 4.55 | ✅ 两层都行（页面底**仅余 0.05**，见下方风险提示） |
| `$dui-ink4 #756E61` | 4.51 ✅ | **4.10 ❌** | ❌ **仅限「卡片底」上的正文** |
| `$dui-ink5 #C7C1B7` | 1.60 | 1.45 | ❌ 装饰线/点专用，任何底都**不得承载文字** |

**判据（两条，各自独立成立）：**

1. **灰的两层判据** —— `ink2` / `ink3` 两层都能用；**`ink4` 只能用于「卡片底」上的正文**。一旦这段文字落在**页面底**上，`ink4` 只有 **4.10**，**不可用于正文**（这与字号无关，别指望靠放大到"大字档 3:1"来救）。选色前若拿不准落哪层，**先确认父容器有没有 `background-color: $dui-card`**——没有就是页面底。
2. **禁止用 `opacity` 降文字层级** —— 降透明度会**同时削弱对比度**，它是**可用性问题**，不是"次级感"的手段。实测：`$dui-vm` 叠 `opacity:.7` → 压卡片底只剩 **3.01**（去掉后回到 4.97）。**要次级感请用「更浅的色」或「更小的字号」，不用透明度。** 透明度只允许作用在**装饰（发丝线、状态点、竖轨）**上。

> ⚠️ **风险提示（非缺陷，但要登记）**：`$dui-ink3 #6C6760` 压**页面底** = **4.55**，**只比 4.5 高出 0.05，没有任何余量** —— 后续任何调色（哪怕轻微压明度）都会让它跌破 AA。**凡改动 `ink3` 或 `$dui-page`，必须重跑 §2.1 全表复算。**

> **为什么这一节存在**：落地前走查的 🔴1.1（对话流景深）、🔴1.2（「往期 →」链接）都是这条链条的下游 —— 令牌注释只标了"卡片 4.51"，读的人以为**到处能用** → `ink4` 被用到**页面底**的对话流 → 4.10 → 再叠 `opacity` → 主屏不可读。所以这里给的是**判据**，而不只是"某处用错了色"的结论。

| `$dui-vm-soft`（朱浅底） | `#F4E8E2`(hue 20°) | **`#F6E6E3`**（hue 9.5°） | 承新朱 **4.59:1** | 与朱同色相（9.6°），色差 ΔE76≈2.1（近乎不可辨）；旧值色相偏调 10° 已弃用 |

> **改动量控制**：以上是「保持色相与饱和档不变、只压明度」的最小改动。若设计上不接受灰阶整体变深，**替代方案**是把所有小字号 ink3/ink4 文字升到 `ink2 (#5A5750)`（已达标 5.85–6.44:1），再补充一档更深的「装饰灰」用于线条——但这会削弱「四档灰」的层级，需设计确认。

### 2.3 用色结论（哪些字能用于正文）

- **正文/小字号（≤18px，含 27rpx/24rpx/23rpx/22rpx）只能用**：`墨 #1A1A18`、`ink2 #5A5750`、`修正 ink3 #6C6760`、`修正 ink4 #756E61`（仅占位，且**仅卡片底**）、`修正 朱 #B83F28`。
- **大字号（≥ 37rpx 常规，或 ≥ 28rpx 加粗）可用 3:1 档**：墨、ink2、**原 ink3 `#8C877E`**、**原朱 `#C8452C`**。
- **纯装饰**：`ink5 #C7C1B7`（线、点）。**朱不是装饰色**——它的小面积用法（色块/图标/文字）必须承载内容含义，须过 §2.4 判据，否则一律不用朱。
- **白字**：只放**墨底**（AAA）；放**朱底**仅 4.60:1，只放图标或大字号。
- **⚠️ 景深文字（对话流）—— 已按 §2.0 两条判据修正**：历史上 `ConversationStream` 曾用 `ink5`/`ink3` + `opacity:.45~.7` 做已播/未播台词，实测跌到 **≈1.0–2.0:1**。**修正后**：已播 `done → $dui-ink3`（页面底 4.55）、未播 `next → $dui-ink2`（页面底 5.85）、当前句 `$dui-ink`（页面底 14.14）；并**去掉文字层上的 `opacity`**——`d1/d2/d3` 的"越远越轻"改由**字号阶梯**（`body → caption → label`）承担。
  → **复核口径**：三种景深层（当前 / 已播 / 未播）在**页面底**上都必须 ≥4.5:1；尤其 `ink4` **不得出现在页面底的台词上**（4.10，见 §2.0）。
- **列表条目、历史分组标题、日期**（`daily .n-date`、`history .g-count`、`TaskListItem .who` 等）当前用 ink5/ink3 小字号 → 统一按 2.2 修正值。

### 2.4 朱的使用判据（防同类误判）

> 只列「哪些地方能用朱」，遇到没列到的场景还会再误判一次，所以这里给**判据**而不只是例子。

**朱标记的是「内容里需要注意的东西」**（某句台词、某处待确认、某个可执行动作）。

- **判据**：如果某处朱色**被去掉**，用户会**漏掉内容信息** → 该用朱；
  如果去掉后**只是"少了个装饰"、或"当前位置不明"** → **不该用朱**。
- **禁用范围**：**导航 chrome**（tabBar 选中态、顶栏）、**分区线/分隔线**、**纯装饰** —— 一律不用朱。
- **合法用途（仅内容区）**：乙的竖轨与台词、待确认状态点、可执行动作文字、当前句标记、朱色圆按钮（上传）、朱浅底上的朱字。
- **措辞限定**：本文中「当前项」**仅指内容区的当前项，不含导航 chrome**（tabBar 的"当前所在"属位置信息，用墨，不用朱）。

- **环境型动效**（呼吸点、旋转弧、持续变形）：按时长判 —— `>200ms` 且非必要即包。
- **交互触发型动效**（按压、点击反馈）：由 **WCAG 2.3.3 Animation from Interactions** 直接管辖，**不看时长**，只要非必要（可被非动效手段替代）就应可关闭。

## 6. 手工同步点（改令牌时必须手改）

> `uni.scss` 是唯一真源，但**有两处地方够不着 SCSS 变量**，必须手工同步。**改任何令牌前，先按下表定位它有没有被引用** —— 否则会出现"令牌变了、这几处没跟"的静默不一致。

### 6.1 ① 原生配置 `pages.json`（4 令牌 / 7 处）

| 令牌 | 色值 | 位置 | 处数 |
|---|---|---|---|
| **`$dui-page`** | `#EDE7D9` | `globalStyle` 的 `navigationBarBackgroundColor` / `backgroundColor` / `backgroundColorTop` / `backgroundColorBottom` | **4** |
| `$dui-ink3` | `#6C6760` | `tabBar.color` | 1 |
| `$dui-ink` | `#1A1A18` | `tabBar.selectedColor` | 1 |
| `$dui-card` | `#F5F2EA` | `tabBar.backgroundColor` | 1 |

**⚠️ 为什么 `$dui-page` 最容易漏**：核对时若只盯 `tabBar` 逐项对，就不会想到 `globalStyle` 里还藏着 4 个字段。而漏它后果最重 —— **全站每个页面顶部（导航栏）与上下背景都会出现一道色差**，是最扎眼的一处。
→ **所以第一步不是"同步 pages.json"，而是"先列出被硬编码的令牌（含 `globalStyle` 的 `$dui-page`×4）"，再逐条同步。**

（`navigationBarTextStyle:"black"`、`borderStyle:"white"` 是枚举值不是十六进制，无需同步。）

### 6.2 ② JS / 模板上下文（够不着 SCSS 变量）—— **与 ① 是两个独立同步面**

| 文件:行 | 值 | 用途 |
|---|---|---|
| `pages/history/history.vue:238` | `#C8452C` →`#B83F28` | `showModal confirmColor` |
| `pages/admin/banners/index.vue:51` | `#C8452C` →`#B83F28` | `showActionSheet` 菜单项色 |
| `pages/admin/banners/index.vue:120` | `#C8452C` →`#B83F28` | `confirmColor` |
| `pages/admin/users/index.vue:63` | `#C8452C` →`#B83F28` | 菜单项色 |
| `pages/admin/users/index.vue:119` | `#C8452C` →`#B83F28` | `confirmColor`（三元，另一支 `#1A1A18`） |
| `components/AdminTable/AdminTable.vue:26` | `#5A5750`（= `$dui-ink2`） | `:style` 的 JS 兜底默认值 |
| `pages/index/index.vue:41` | `#fbf9f4`（= `$dui-on-ink`） | 内联 `<svg stroke>` |

合计 **7 处：5×朱 + 1×ink2 + 1×on-ink**。
> `<script>` 与模板属性引用不到 SCSS 变量，属**合法硬编码**，但**值必须与令牌一致** —— 本轮就出现过 5 处旧朱残留（令牌已 `#B83F28`，JS 仍 `#C8452C`；对比度不违规，属一致性 🟡）。

### 6.3 改令牌时的 checklist（顺序不可颠倒）

1. 改 `uni.scss` 令牌值
2. **先判断该令牌是否被 ①/② 引用**（`pages.json` 会被引用的：`page` / `ink3` / `ink` / `card`；JS/模板：朱 / `ink2` / `on-ink`）
3. 同步 `pages.json` —— **含 `globalStyle` 的 4 处**
4. 同步 JS / 模板硬编码（§6.2）
5. 重扫 `.vue` `<style>` 写死色（应为零）
6. **若改的是亮色系（`ink3`/`ink4`/`ink5`）→ 重导 tab 图标**（PNG，config 管不到）
7. 重新编译并 grep 产物 —— ⚠️ **先关 HBuilderX GUI**，否则 `unpackage/dist` 会被中途重写，读到半成品会误判
